# Руководство программиста приложения SudOcean

Данный документ описывает архитектуру, структуру данных и механизмы интеграции мобильного приложения SudOcean с системой 1С:Предприятие.

## 1. Архитектура приложения
Приложение реализовано в соответствии с принципами **Clean Architecture** и паттерном **MVVM**.

*   **UI Layer**: Фрагменты используют ViewBinding для безопасного взаимодействия с компонентами интерфейса.
*   **ViewModel Layer**: Управляет состоянием UI и взаимодействует с репозиторием через Coroutines.
*   **Data Layer (Repository)**: Реализует логику выбора источника данных (Network или Local DB).

## 2. База данных (Room)
**Текущая версия БД**: 8.

### Основные сущности:
*   `User`: Включает поле `remoteId` (уникальный индекс), которое служит ключом синхронизации с 1С. Хранит данные профиля и тип авторизации.
*   `Product`: Кеш номенклатуры. Содержит информацию об остатках (`stock`) и категориях.
*   `CartItem`: Локальное хранилище корзины, привязанное к `userId`.
*   `Order` & `OrderItem`: Заказы, синхронизируемые с 1С.

## 3. Механизм авторизации и безопасности
В приложении реализована **гибридная схема авторизации** (`LoginViewModel`):
1. **Локальный вход**: Проверка данных в Room. Если пользователь найден, выполняется фоновый запрос в 1С (`verifyUserRemote`) для подтверждения актуальности аккаунта.
2. **Удаленный вход**: Если в локальной БД пользователя нет, выполняется запрос к REST-сервису 1С. При успехе данные кэшируются локально.

### Меры безопасности:
*   **Криптография**: Пароли передаются по HTTPS. На стороне 1С реализовано хеширование по алгоритму SHA-256.
*   **Защита UI**: Использование `WindowManager.LayoutParams.FLAG_SECURE` на критических экранах (оплата) для предотвращения утечки данных через скриншоты или захват видео.
*   **Обфускация**: Применение ProGuard/R8 для защиты кода и строковых констант.

## 4. Интеграция с 1С (REST API)
Взаимодействие происходит через HTTP-сервис `MobileExchange`.
*   **Аутентификация**: Basic Auth с токеном, закодированным в Base64.
*   **Синхронизация товаров**: Реализована через `syncProducts()` в репозитории. Поддерживает обновление цен и остатков.
*   **Передача заказов**: При оформлении заказа в 1С отправляется JSON-объект, содержащий данные контрагента и состав корзины. В ответ приложение получает номер заказа и платежные реквизиты (QR/ссылка).

## 5. Технический стек
*   **Kotlin Coroutines & Flow**: Для асинхронной работы и реактивного обновления UI.
*   **Retrofit 2 & OkHttp**: Сетевой стек с интерцепторами.
*   **Room Persistence Library**: Локальное хранилище с поддержкой миграций.
*   **Navigation Component**: Централизованное управление переходами.

## 6. Рекомендации по развертыванию
1. Для корректной работы генерации PDF-счетов в 1С, у пользователя, под которым работает сервис, должна быть установлена роль с правами на просмотр и печать документов.
2. При изменении структуры БД необходимо увеличивать версию в `AppDatabase.kt`. Текущая стратегия — `fallbackToDestructiveMigration()`.
