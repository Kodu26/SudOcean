# Руководство программиста приложения SudOcean

Данный документ описывает архитектуру, структуру данных и механизмы интеграции мобильного приложения SudOcean с системой 1С:Предприятие.

## 1. Архитектура приложения
Приложение построено на базе архитектурного паттерна **MVVM (Model-View-ViewModel)** с использованием компонентов Google Jetpack.

*   **View (Фрагменты)**: Ответственны за отображение UI и обработку действий пользователя. Используется ViewBinding.
*   **ViewModel**: Хранит состояние экрана и обрабатывает бизнес-логику. Общается с репозиторием.
*   **Model (Repository)**: Единая точка доступа к данным. Репозиторий решает, взять данные из локальной БД (Room) или из сети (Retrofit).

## 2. База данных (Room)
Схема БД включает следующие сущности:
*   `User`: Хранит данные текущего пользователя (Тип лица, ФИО, ИНН, КПП, Телефон).
*   `Product`: Кешированный список товаров из 1С.
*   `CartItem`: Товары, добавленные в корзину.
*   `Order` & `OrderItem`: Заголовки и детальный состав заказов (синхронизируются с 1С).

**Версия БД**: 4 (используется `fallbackToDestructiveMigration` при разработке).

## 3. Сетевое взаимодействие (Retrofit)
Связь с 1С осуществляется через REST-подобный HTTP-сервис.
*   **Base URL**: Настраивается в `NetworkClient.kt`.
*   **Авторизация**: Basic Auth (логин/пароль администратора 1С).
*   **Основные эндпоинты**:
    *   `GET /products` — Загрузка номенклатуры.
    *   `POST /clients` — Синхронизация данных контрагента.
    *   `POST /orders` — Отправка нового заказа.
    *   `GET /orders` — Загрузка истории по `user_id`.
    *   `POST /orders/cancel` — Программная отмена.

## 4. Логика синхронизации
Приложение использует гибридную схему:
1.  **Каталог**: Обновляется принудительно жестом Swipe-to-Refresh.
2.  **Профиль**: При сохранении данных в приложении отправляется синхронный запрос в 1С.
3.  **Заказы**: При открытии истории приложение удаляет локальные заказы и перезаписывает их данными из 1С, гарантируя актуальность статусов и номеров.

## 5. Настройка Backend (1С)
Для работы системы в 1С должен быть опубликован HTTP-сервис `MobileExchange`.
*   **Кодировка**: Все ответы сервера должны быть в **UTF-8**.
*   **Формат даты**: ISO 8601 (`yyyy-MM-ddTHH:mm:ss`).
*   **Поиск**: Контрагенты ищутся по уникальному реквизиту `ID_МобильногоПользователя` (тип Строка).

## 6. Используемые библиотеки
*   `Retrofit 2` + `Gson`: Сетевые запросы.
*   `Room`: Локальное хранилище.
*   `Navigation Component`: Навигация между экранами.
*   `SwipeRefreshLayout`: Жесты обновления данных.
